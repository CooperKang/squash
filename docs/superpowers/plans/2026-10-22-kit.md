# 소모품 상담 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 장비 섹션에 선생님이 고민 상담해 주듯 답하는 "소모품 상담" 화면을 만들고, 팁에 필요한 소모품에 쿠팡 파트너스 링크(`partners.json`)를 붙인다.

**Architecture:** 상담 내용은 `src/data/kit.ts`, 상품 링크는 사람이 고치는 `src/data/partners.json`과 이를 읽는 `src/data/partners.ts`로 나눈다. 화면 `src/pages/Kit.tsx`는 기존 라우터(`parent: 'gear'`)와 `SEO_PAGES` 프리렌더를 그대로 탄다. 빌드 마지막에 프리렌더 결과를 검사해 대가성 문구가 첫 쿠팡 링크보다 앞에 없으면 빌드를 실패시킨다.

**Tech Stack:** React 19, TypeScript, Vite, Tailwind 4, Vitest, `scripts/prerender.mjs`

**Spec:** `docs/superpowers/specs/2026-10-22-kit-design.md`

## Global Constraints

- 대가성 문구는 정확히 `이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.` 이고 `DISCLOSURE` 한 곳에서만 가져다 쓴다.
- 문구는 페이지 첫 부분(머리말 제목 바로 아래, 칩·상담보다 위), 테두리 상자, 본문과 다른 색(teal 계열)·굵은 글씨. 링크 묶음마다 바로 위에 한 번 더(작게).
- 쿠팡 링크는 `target="_blank" rel="sponsored nofollow noopener"`. 상담 화면 밖에는 쿠팡 링크를 달지 않는다.
- `partners.json`의 `url`은 빈 문자열이거나 `https://link.coupang.com/`로 시작. `url`이 있으면 `name`도 있어야 한다.
- 상담 카드 하나에 상품 최대 3개. 보여 줄 상품이 없으면 링크 묶음(작은 문구 포함)을 통째로 감춘다.
- `note`는 써 본 것처럼 쓰지 않는다(상품 특징·고르는 기준만).
- 말투: 기존 사이트처럼 "~해요" 체. 상담 답은 공감 → 이유 → 해결, 2~4문장.
- 라켓 구매 링크(영산스포츠)는 건드리지 않는다.

## Review Focus

- 사용자가 GitHub 웹에서 `partners.json`을 고치다 일반 쿠팡 주소(`www.coupang.com/vp/...`)를 넣음 → 테스트가 실패해 배포가 막혀야 한다(Task 1 테스트).
- 공유된 주소의 `c`/`g` 값이 없는 id(`#/kit?c=foo`) → 화면이 깨지지 않고 전체 목록을 보여 준다(Task 2 테스트).
- 모든 상품이 빈 상담 → 팁은 보이고 링크 묶음과 작은 문구는 안 보인다(Task 1 `picksFor` 테스트).
- 휴대폰(390px) 첫 화면에 대가성 문구 상자가 보인다(Task 4 눈 확인).
- 품목 정적 페이지(`/kit/grip/`)로 들어온 사람도 대가성 문구가 링크보다 먼저 나온다(Task 4 빌드 검사).

**Files:**
- Create: `src/pages/Kit.tsx`, `src/router.test.ts`
