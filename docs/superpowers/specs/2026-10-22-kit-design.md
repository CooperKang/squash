# 소모품 상담 설계

2026-10-22

## 목적

스쿼시를 치며 생기는 고민(손에 땀이 많다, 발목이 약하다, 그립이 얇았으면 좋겠다 등)에 스쿼시 선생님이 상담해 주듯 답하는 팁 콘텐츠를 만든다. 팁을 따르는 데 필요한 소모품에는 쿠팡 파트너스 링크를 붙여 수익을 낸다.

- 주인공은 팁이다. 쇼핑몰처럼 상품을 늘어놓지 않는다. 상담 하나에 링크는 1~2개.
- 쿠팡 파트너스 최종 승인에 낼 "링크가 게시된 페이지" 스크린샷도 이 화면으로 찍는다.
- 라켓 구매는 지금처럼 영산스포츠(라켓 찾기)로 연결하고, 쿠팡은 소모품에만 쓴다.

## 위치와 주소

- 새 화면 `kit`(이름 "소모품 상담", 짧은 이름 "소모품"), `parent: 'gear'`. 장비 섹션 탭이 `장비 | 라켓 찾기 | 소모품 상담`이 된다.
- 앱 주소: `#/kit`, 품목 `#/kit?g=grip`, 상담 하나 `#/kit?c=sweat-hand`(해당 상담으로 스크롤, 공유용).
- 정적 페이지(`src/seo.ts`의 `SEO_PAGES`에 추가, `scripts/prerender.mjs`가 만든다):
  - `kit/` 고민 모아보기
  - `kit/grip/` 그립
  - `kit/shoes/` 신발
  - `kit/sweat/` 머리띠·손목밴드
  - `kit/protect/` 보호안경·발목 보호대
  - `kit/recovery/` 폼롤러·공

## 화면

1. 머리말(`PageHead`): "치다 보면 생기는 고민, 소모품으로 풀리는 것들" 정도의 소개. 바로 아래에 경제적 이해관계 표시 상자(아래 규칙).
2. 고민 칩: "나는…" 아래에 고민 칩을 늘어놓는다. 누르면 해당 상담으로 스크롤하고 주소의 `c`를 바꾼다.
3. 품목 탭: 전체 / 그립 / 신발 / 땀 / 보호 / 회복. 고르면 `g`를 바꾼다.
4. 상담 카드(품목별로 묶음):
   - **Q.** 고민을 사용자 말투로("레슨 30분만 지나면 라켓이 손에서 돌아요")
   - **A.** 선생님 말투의 답(공감 → 이유 → 해결). 2~4문장.
   - **이렇게 해 보세요**: 물건 없이 할 수 있는 실천 팁 1~3개
   - **고를 때 볼 것**: 기준(예: 드라이·흡수형, 두께 0.6mm 안팎)과 링크 1~2개("쿠팡에서 보기 ↗")
5. 링크 묶음 바로 위에 작은 대가성 문구.
6. 맨 아래: 장비 고르기, 라켓 찾기로 가는 연결.

| sore-calf | recovery | 다음 날 종아리가 뭉쳐요 | foam-roller |
| dead-ball | recovery | 공이 안 튀어서 랠리가 안 돼요 | ball |

그립 상담의 핵심 내용:
- 땀이 많으면: 끈적(택키)형은 젖으면 오히려 미끄럽다. 타월형이나 드라이(흡수)형, 자주 교체.
- 얇은 그립이 좋으면: 원그립(기본 그립)을 벗기고 얇은 그립이나 오버그립 한 겹만.
- 두꺼운 그립이 좋으면: 원그립은 두고 그 위에 오버그립을 덧감는다.
- 새 라켓: 원그립은 따로 팔지 않아 한 번 벗기면 되돌리기 어렵다. 바로 벗기지 말고 오버그립을 올려 몇 번 쳐 본 뒤, 두껍게 느껴지면 그때 벗기고 아니면 그대로 둔다. 오버그립 교체 주기(땀 많으면 2~3주)도 여기서 안내.

## 데이터

- `src/data/kit.ts`
  - `KIT_GROUPS`: `{ id: 'grip' | 'shoes' | 'sweat' | 'protect' | 'recovery'; label; path }`
  - `KIT_TIPS`: `{ id; group; chip; q; a; tries: string[]; look: string; links: PartnerKey[] }`
- `src/data/partners.json`: 사람이 직접 고치는 상품 목록. 코드를 몰라도 이 파일만 고치면 된다(GitHub 웹에서 고치면 배포까지 자동).
  ```json
  "grip-towel": {
    "label": "타월 그립",            // 묶음 이름
    "search": "스쿼시 타월 그립",     // 링크 만들 때 쓴 검색어(기록용, 화면에 안 나옴)
    "items": [
      { "name": "OO 타월 그립 3개입", "url": "https://link.coupang.com/...", "note": "땀 많은 날 2주면 갈아요" }
    ]
  }
  ```
  - 키 하나에 상품을 여러 개 넣을 수 있다. 상담 카드에는 상담에 걸린 키들의 상품을 순서대로 최대 3개까지 보여 준다.
  - `note`는 선택. 있으면 상품 이름 아래 한 줄 코멘트로 보여 준다. 사용자가 비워 두면 Claude가 상품 특징 기준으로 채운다(아래 표시 규칙 참고).
  - `url`이 빈 항목은 화면에 안 나온다. 상담에 보여 줄 상품이 하나도 없으면 링크 묶음만 감추고 팁은 그대로 보여 준다.
- `src/data/partners.ts`: JSON을 읽어 타입을 붙이고 빈 항목을 거른다. `DISCLOSURE` 문구("이 글에는 쿠팡 파트너스 링크가 있어요. 링크로 구매하시면 일정액의 수수료를 받아요.")도 여기 둔다.
- 링크는 파트너스 사이트의 링크 생성으로 만든 것만 쓴다. 파트너스 코드로 주소를 직접 조립하지 않는다(추적이 보장되지 않음).

## 링크

- `<a href target="_blank" rel="sponsored nofollow noopener">`. 스타일은 기존 바깥 링크(라켓 찾기의 구매 링크)를 따른다.

## 경제적 이해관계 표시(필수)

쿠팡 파트너스 경제적 이해관계 표시 가이드와 공정위 추천·보증 심사지침(2024-12-01 개정)을 따른다.

- 문구는 쿠팡 권장 문구 그대로 쓴다: **"이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다."** "파트너스 링크가 있어요" 같은 줄이거나 모호한 표현은 쓰지 않는다. `partners.ts`의 `DISCLOSURE` 한 곳에만 두고 모든 곳에서 가져다 쓴다.
- 위치: 페이지 **첫 부분**. 머리말 제목 바로 아래, 고민 칩과 상담보다 위. 스크롤하지 않아도 보여야 한다(휴대폰 포함). 글 맨 아래에만 두지 않는다.
- 모양: 본문과 구별되게. 테두리 있는 상자에 본문보다 크거나 굵은 글씨, 본문과 다른 색(사이트 강조색). 접거나 숨기지 않는다.
- 링크 묶음마다 바로 위에 같은 문구를 한 번 더 작게 둔다(상담 링크로 바로 들어온 사람도 링크 전에 보도록).
- 다른 화면에서 소모품 상담으로 보내는 연결 문구에는 쿠팡 링크를 직접 달지 않는다(상담 화면 안에서만 링크).
- 정적 페이지(`dist/kit/**/index.html`)에도 본문 첫 부분에 문구가 들어간다.
- `note`(상품 한 줄 코멘트)는 실제로 써 본 것처럼 쓰지 않는다. 상품 이름과 상세에서 확인되는 특징이나 고르는 기준만 적는다(예: "흡수형이라 땀이 많은 손에 맞아요"). 거짓 사용 후기는 심사지침 위반이다.

## 기존 화면에서 연결

- 장비(`Gear.tsx`)의 그립·신발·보호안경 카드 → `#/kit?g=grip` 등.
- 혼자 연습 > 운동 후 스트레칭의 폼롤러 설명 → `#/kit?c=sore-calf`.
- 라켓 찾기 결과 아래 → "그립 고민 상담" `#/kit?g=grip`.

## 테스트

- `src/data/kit.test.ts`
  - 모든 상담의 `links` 키가 `partners.json`에 있다.
  - 상담 id와 칩이 겹치지 않는다.
  - 모든 품목에 상담이 하나 이상 있고 `SEO_PAGES`에 품목 페이지가 있다.
  - `partners.json`에서 `url`이 있는 항목은 `name`도 있고, `url`은 `https://link.coupang.com/`로 시작한다(잘못 붙여 넣은 일반 쿠팡 주소를 잡는다).
- `npm run build` 뒤 `dist/kit/` 아래 모든 `index.html`에서 대가성 문구가 첫 쿠팡 링크보다 앞에 나오는지, 쿠팡 링크마다 `rel="sponsored`가 있는지 스크립트로 확인.
- 휴대폰 폭(390px)에서 첫 화면에 문구가 보이는지 눈으로 확인.
