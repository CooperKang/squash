# 상대 AI 난이도 분석 및 조정

2026-10-20, 기준 커밋 `2367332` 대비 로컬 Chrome에서 비교했다.

## 확인한 원인

- 기존 보통·어려움은 좋은 샷(`sharp=1`)의 리턴 확률이 드라이브에서 54%·61%, 짧은 샷에서 44%·51%였다. 공에 닿아도 확률로 포기하는 비중이 컸다. 쉬움만 별도로 강화되어 수비 난이도 순서도 뒤집혀 있었다.
- 기존 `inCpuReach`는 앞 코트 발리를 배제하고, 한 번 튄 공은 하강 구간에서만 허용했다.
- 모션 도입 후 2차원 이동을 검사하게 되었지만 공 위치까지의 직선 거리로 판단했다. 실제로 서는 옆자리, 가속·감속을 반영한 타점 예측이 필요했다. 타구 후 중앙 복귀도 게임 시간 0.5초 뒤에 2.8m/s로 시작했다.
- 샷 후보가 없을 때 검증 없이 중앙 높이 2.6m를 겨냥했다. 앞벽 가까운 위치에서는 공이 높게 떠 아웃될 수 있었다.
- 로컬 측정에서 관절 계산은 최대 약 0.2ms였다. 이 환경에서는 모션 계산이 주된 실패 원인이라는 근거가 없었다. 실제 휴대폰 기기 성능은 측정하지 않았다.

## 변경

`src/game/cpu.ts`에 수비·이동·복귀·공격 설정을 함께 두었다. 어려울수록 확률 실수를 줄이고, 반응과 이동·복귀를 빠르게 하며, 더 예리한 샷과 짧은 수비 가능 시간을 허용한다. 쉬움의 멈춰서 샷을 고르는 방식은 유지한다.

타점 선택은 공의 궤적과 실제 이동식을 함께 사용한다. 관절의 표시 상태로 리턴 여부를 결정하지 않는다. 앞 코트 발리와 바운드 직후 상승 중인 공도 후보가 된다. 도달 불가능한 공은 그대로 놓친다.

예측과 실제 공·몸 갱신은 1/240초 간격으로 맞췄다. CPU 샷도 같은 간격으로 검증한다. 우선순위 후보가 실패하면 이미 규칙과 수비 가능 구간을 확인한 후보를 재사용하거나 별도의 안전한 샷을 탐색한다.
